does not establish a general ranking or justify replacing the current workflow.

All 36 trial configurations, token receipts, independent verdicts and final
workspace hashes reconciled through `audit.py`. Five attempts reached the
independent judge and passed. The other 31 stopped at conservative budget
admission, including worker refusals that surfaced as an SDK error in the
conductor. These are unfinished attempts, not measured source-code failures.

The proxy reserves estimated input tokens, protocol allowance and completion
capacity before each request. It can refuse a request while actual usage remains
below the nominal 30000-token ceiling. This constraint was the dominant failure
mode and is a limitation of this configured comparison. A shorter failed run is
not an accepted-code speedup. Monetary subscription costs are unknown; token
counts are not dollar-cost measurements.

A replacement needed at least two additional accepted trials relative to
baseline, or equal acceptance with a measured 20 percent cost reduction, plus
passing lifecycle/admission gates. Neither completion threshold was met, and
unknown costs cannot establish the alternative savings criterion. The frozen
selection policy also retains baseline when a candidate has failed run gates.
Baseline retention is a conservative default, not a claim that baseline passed
every gate or is the best harness generally.

## What was compared

Six authored development tasks over pinned repository source, repeated twice per
arm: task-ID validation, ownership API extension, compiling/running Omega,
independent multiworker edits, atomic conflicting claims and ownership recovery.
They are public development cases, not an unseen general benchmark. The original
`coder/eval` held-out task corpus was not used or exposed.

Every arm used the same `openai-codex/gpt-5.6-sol` route, low reasoning effort,
1024-token completion cap, 30000-token aggregate admission budget and 1200-second
run deadline. Trials ran one at a time in a deterministic shuffled order, seed
498. Framework prompts and their configured tool/context behavior remained part
of the comparison. Workers could write only declared paths; the conductor could
read/check and delegate. No prompts or judges changed during the scored campaign.

The model's immutable hosted weight revision is not exposed. This records the
requested route and observed response labels, not a checkpoint qualification.
The controller ran on Linux AArch64; inference used existing hosted subscription
access. No GPU performance or production-runtime claim follows from these runs.

## Verification and release boundaries

Before scoring, 31 focused software checks, seven actual Docker boundary checks,
and all six negative-start/positive-reference acceptance controls passed. Failed
preflights were retained and contained no scored model requests. Each run then
retained its raw failures, provider usage, SDK logs, durable events, independently
hashed workspace and independent judge output. Raw content stays private on the
operator's development host; this directory publishes reviewed outcomes/hashes.

After the frozen campaign, command-output capture was hardened to refuse output
above 16000 bytes without buffering it unboundedly. Unconfirmed sandbox cleanup
now cancels further authority. This hardening was developed separately and did
not alter the recorded trial implementation or replace any trial. Final source
passed 34 focused checks, the seven Docker boundaries and all six judge controls
again. A real abrupt-process-exit control verified rollback before pointer commit,
recovered integration, idempotent retry, original-snapshot preservation and
persistent cancellation. The full trial set was not rerun against the hardening;
its measurements apply to the frozen trial commit above.

An advisory source review identified eight important issues that were fixed and
covered by regression checks. Agent review is not independent hardware or
scientific qualification. The deterministic judges are separate from agent
execution, but do not certify resistance to arbitrary malicious Python code.
The iMac runner was unreachable. Focused checks ran on the development host;
unchanged language examples and unrelated full builds were not rerun.

## Delivery decision

Keep all three pilot adapters available for development experiments and retain
OMP as the regular workflow. Do not purchase LangSmith or move Atlas/Cortex based
on this pilot. Tracing-platform selection and production integration remain
separate follow-on work. This release changes experimental coding tooling only.
